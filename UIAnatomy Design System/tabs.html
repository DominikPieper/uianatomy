Tabs

A Tabs component lets one of several panels be visible at a time, with a row of tab triggers selecting between them. The selected tab is announced via aria-controls and aria-selected; the active panel is referenced back via aria-labelledby.

Compound component pattern. Selection state lives on Tabs.Root and is shared via context. Slots are referenced by name, not by DOM order.

// Headless API · framework-agnostic shape <Tabs.Root defaultValue="anatomy" orientation="horizontal"> <Tabs.List> <Tabs.Trigger value="anatomy">Anatomy</Tabs.Trigger> <Tabs.Trigger value="axes">Axes</Tabs.Trigger> <Tabs.Trigger value="bridge">Bridge</Tabs.Trigger> <Tabs.Indicator /> </Tabs.List> <Tabs.Panel value="anatomy">…</Tabs.Panel> <Tabs.Panel value="axes">…</Tabs.Panel> <Tabs.Panel value="bridge">…</Tabs.Panel> </Tabs.Root>

Bridge view

§ 3

Where Figma and code line up — and where they don't. The yellow column marks every point at which the designer artifact and the implementation drift.

Figma

Tabs is a single component with three Variants and one Instance Swap (tabs).

Selected tab is captured by a selectedIndex Number property — purely visual.

Each Tab is its own component instance; the list is reorderable in the layer panel.

Code

Tabs.Root is a context provider; children are addressed by value not index.

Selection lives in state — controlled (value) or uncontrolled (defaultValue).

Order is determined by JSX position, but matching is by value string.

Mismatches

1 · Index vs. value

Figma selects by integer index; code selects by string value. A reorder in Figma silently shifts the "selected" tab; in code it does nothing.

FIGMA
selectedIndex = 1
⇄
CODE
value="axes" · defaultValue="axes"
2 · Indicator animation

The animated underline that slides between tabs is captured in Figma as an Auto Layout transition between variants — it is implemented in code as a measured offset on a single absolutely-positioned element.

FIGMA
Smart Animate between variants
⇄
CODE
Tabs.Indicator with measured transform: translateX()
3 · Manual activation

"Manual activation" (arrow keys move focus, Enter selects) has no Figma representation — designers see only the selected state, not the focus-but-not-selected intermediate.

FIGMA
Not represented
⇄
CODE
activationMode="manual" · tabIndex rotation
4 · Disabled tab semantics

A disabled tab in Figma is a state on the Tab variant. In code it is both aria-disabled="true" and removal from arrow-key rotation — the latter is not visible in the design.

FIGMA
Tab · state = disabled
⇄
CODE
aria-disabled + skip in roving tabindex
